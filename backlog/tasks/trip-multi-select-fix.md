# Исправление: выбор нескольких мест поездки

## Исходный запрос

«теперь я не могу добавить несколько мест в поездку, убирается выбор после того, как я пытаюсь выбрать второе место».

Уточнение координатора после исследования: места разных city одного региона должны оставаться выбранными и входить в общий маршрут; регионы сохраняются раздельными. Исправление только значков недостаточно. Существующие locationTrips мигрировать без потерь/дублей, прежние настройки по возможности сохранить. Названия конкретных мест дополнительно запрошены пользователю, ответ не препятствует подтверждённому исправлению.

Ограничения: сохранять прежний функционал отдельной /trip, автоматические оценки посещения, три режима, инструкции/fallback, Яндекс-ссылки с делением после 10 точек, локальное/серверное сохранение и JSON. Существующие незакоммиченные изменения не откатывать; публикация и объединение разных регионов не поручены.

## Подтверждённый анализ и воспроизведение

Исследована текущая production-сборка http://localhost:3000 в чистых браузерных контекстах Chrome desktop 1440×1000 и iPhone 13. Никакой preseed поездки, перехват API или route fixtures не использовались. Все добавления — обычными кнопками ленты.

- В одной city: выбор региона «Коломна и окрестности», добавление кремля, Лажечникова и Зайцева последовательно дают 1/2/3 выбранных места и trip из трёх id. Общий сброс на втором клике одной city не воспроизведён.
- Между city: в начальной Карелии добавить «Суйсари на острове», затем «Река Сюскюянйоки». После обоих кликов визуально выбранной остаётся одна карточка; Суйсари снова имеет действие «Добавить». /trip показывает только реку. Выбор «Онежское озеро» в /trip возвращает Суйсари, reload сохраняет его. То же на mobile. Значит, первая точка сохранена в другом bucket, но исчезает из видимого выбора и общего маршрута.
- Причина: `components/explorer.tsx:addToTrip` на каждом добавлении вызывает `setTripLocation(placeLocationId(place))`. `lib/locations.ts:locationId` группирует по region + city; `lib/store.ts:setLocation` заменяет активный trip массивом выбранной city. Значки ленты, видео и карточек читают только `trip`. `TripPanel` дополнительно фильтрует stops по placeLocationId. Совокупность кода не даёт общей поездки между city региона.
- Добавление `addPlace(place)` в последней реализации меняет allPlaces, но само по себе не объясняет потерю: одинаковая city проходит 3 клика, query-effect очищает URL через replaceState. Не исправлять эту гипотезу без отдельного доказательства.

## Минимальный план и зависимости

1. **Регион как граница поездки, без перестройки каталога.** В store сделать `regionTrips` и текущий `trip` авторитетными для выбранного regionId. Выбор city/location оставить контекстом просмотра/избранного, который не заменяет региональный trip. Переключение региона сохраняет и восстанавливает отдельный trip. Добавление в том же регионе не переключает поездку между city. Метаданные transient мест продолжать сохранять для прямого /trip.
2. **Совместимая однократная миграция.** Новый отдельный флаг/версия миграции (старый locationsMigrated не переиспользовать как доказательство новой миграции). Активный trip учитывать как наиболее свежую версию активного bucket, чтобы не воскресить удалённые остановки из устаревшего locationTrips. Объединять сохранённые city buckets с актуальными regionTrips соответствующего региона, дедуплицировать, сохранять порядок внутри исходных массивов, текущий пользовательский порядок — приоритетный. Повторный sync/reload не импортирует устаревшие city buckets заново. Неизвестные id оставлять в отложенных данных до загрузки метаданных. Старые daySettings не удалять: для новых региональных настроек использовать существующие региональные, иначе активную city и default; исходные city-настройки сохранять. Если миграция объединяет больше 20 точек, не обрезать молча: сохранить весь набор и явно попросить сократить до лимита перед расчётом, новые добавления сверх лимита запрещены. Зависит от 1.
3. **Все входы и /trip.** Лента, map→карточка, video-reel, полоса остановок должны читать один региональный trip. В TripPanel убрать city-фильтр остановок, показывать места из текущего региона; переключатель поездки должен выбирать регион, а не скрытно дробить маршрут по city. Список сохранённых для добавления — из всех city региона. Разделение сохранённого по city в каталоге можно сохранить. Route signature/invalidation и описания UI привести к региональной поездке, убрать обещания «только одна локация». Изменение city просмотра/возврат из place deep link не теряет trip. Рекомендации минимально адаптировать для региональной области там, где текущая city-фильтрация конфликтует с новой поездкой; не расширять число/принципы проверяемых рекомендаций. Зависит от 1–2.
4. **Проверки разработчика и независимое QA.** Содержательные unit регрессии store/migration; E2E обычным UI на обоих размерах без preseed для основного сценария и без route fixtures для выбора/переходов. Отдельные storage fixtures допустимы только для миграции; route fixture допустим для детерминированной проверки передачи всех выбранных координат в расчёт, не как замена пользовательскому выбору. Запустить затронутые тесты и lint/typecheck; новую сборку передать отдельному tester. Обновлять состояние/implementation/QA в этой карточке. Зависит от 3.

## Критерии приёмки

1. Чистая пользовательская сессия desktop/mobile: добавление 2, затем 3 разных мест одного региона из разных city оставляет все ранее выбранные карточки выбранными; счётчик/полоса и /trip содержат все 2/3 остановки. Проверить Карелию (Суйсари, Сюскюянйоки, третья city) и минимум два места разных city Коломны.
2. Три места одной city (кремль, Лажечникова, Зайцева) также остаются выбранными. Повторное нажатие снимает только указанное место, остальные сохраняются; повторное добавление не создаёт дублей.
3. После удаления одной из трёх, перехода каталог → /trip → каталог и reload сохраняются ровно две ожидаемые остановки, порядок и состояние кнопок. Из /trip можно снова добавить третью через каталог; прямой /trip показывает тот же набор.
4. Карта → карточка места, лента и video-reel согласованно показывают выбор, добавляют/снимают отдельные точки региональной поездки. Просмотр другой city и возврат через place URL не теряют уже выбранные места. Основной сценарий проверен реальными кликами без storage seed.
5. Построение маршрута получает все выбранные точки региона в текущем порядке, итог описывает их все, Яндекс-ссылки и JSON включают весь набор. Удаление/перестановка обновляет итог. Неизвестное время/недоступность провайдеров честно отображаются, прежние три режима и авто-длительности сохраняются.
6. Переключение Карелия → Коломна → Карелия восстанавливает отдельные наборы регионов без смешивания; добавление в Коломне не удаляет Карелию. Выбор city для каталога/сохранённого не подменяет региональный trip.
7. Миграция существующего storage с несколькими locationTrips одного региона объединяет все актуальные остановки без дублей и потерь. Активные удаления не воскресают из устаревшего bucket; повторный sync/reload идемпотентен. Неизвестные id не удаляются до загрузки места; прежние настройки доступны/корректно перенесены. Объединение более 20 точек не обрезается молча, расчёт заблокирован до сокращения, новые добавления сверх лимита не допускаются.
8. Нет ошибок браузера, горизонтального overflow или перекрытия действий на desktop/mobile; визуально понятна область поездки — текущий регион. Проверен работающий сайт актуальной сборки, получены скриншоты. Итоговый вердикт выставляет отдельный тестировщик, не разработчик.

### QA-1 — потеря неизвестного ID при удалении другой остановки

- Значимость: **высокая** (потеря сохранённых пользовательских точек; обязательный критерий7).
- Данные: чистый test context, legacy locationsMigrated=true, regionTripsMigrated отсутствует, активный city bucket с10 test customPlaces, второй city bucket с12 customPlaces + `unknown-id`; metadata unknown пока нет. В активном stale bucket также `deleted-id`, отсутствующий в текущем trip. Это исключительно тестовые данные.
- Шаги: открыть `/trip`; дождаться миграции (22 видимых остановки, unknown-id есть в persisted trip/unassignedStops, deleted-id отсутствует); нажать «Удалить QA миграция 0»; reload; прочитать persisted state.
- Ожидается: удалена только qa-migrate-0; unknown-id остаётся в отложенных данных до появления метаданных. Reload не теряет его.
- Фактически: 21 видимая остановка корректно остаётся, но `unknown-id` исчезает из `trip` и `unassignedStops=[]`. Повторено собственным Chrome сценарием. Сохранённый лог `trip-multi-select-fix/qa-failure.log` и точный fixture/script `qa-extra.ts.txt`.
